OCTOBER 26, 2026 — TRACKED AND HOVER SOUND EVENTS CONNECTED

I found that the five WAV files from my original CGS tracked/hover starter pack had ALREADY been added to Mech-Core-CGS under Sounds/Mech. However, Sounds/SampleMech.acp still had ONLY two defined sound events: SOUND_MECH_STEP and SOUND_MECH_SERVO. That's why I couldn't hear the tracked and hover events just by selecting locomotion modes.

WHAT I DID IN MECH CORE
I extended the existing Sounds/SampleMech.acp project (same project GUID) with five spatialized sound events. I reused the established SoundClass > Shader > LocalBank > Mixer wiring from the working footstep and servo sounds, changing each sample resource to its already-imported CGS WAV with its correct resource ID. I left the walker footstep and servo event graphs unchanged.

- SOUND_MECH_TRACK_CLANK uses Sounds/Mech/CGS_Track_Clank.wav
- SOUND_MECH_TRACK_RUMBLE uses Sounds/Mech/CGS_Track_Rumble_Loop.wav
- SOUND_MECH_HOVER_THRUST uses Sounds/Mech/CGS_Hover_Thrust.wav
- SOUND_MECH_HOVER_IDLE_PULSE uses Sounds/Mech/CGS_Hover_Idle_Pulse.wav
- SOUND_MECH_HOVER_IDLE uses Sounds/Mech/CGS_Hover_Idle_Loop.wav

I updated Scripts/Game/Mech/BFA_MechMovementComponent.c with two additional configurable event fields (m_sTrackRumbleEvent and m_sHoverIdleLoopEvent). The existing three one-shot fields are preserved. The client automatically schedules the approximately four-second rolling-track sample while treads move/turn, or a low hover idle bed on hover mechs. Existing track clank, hover whoosh and hover pressure-pulse timings run independently of those beds. The code uses local audio only, with no new sound RPC traffic.

WHAT I DID IN MW
I connected ALL EIGHT tracked/hover frame prefabs (Light, Medium, Heavy, Assault). Each has:
- A root SoundComponent loading Core's {8B7D7D9A72F30BAD}Sounds/SampleMech.acp
- A root SCR_SoundDataComponent with SCR_AudioSourceConfiguration entries for just its track or hover events
- The appropriate locomotion sound-event fields set on BFA_MechMovementComponent

The tracked frames receive SOUND_MECH_TRACK_CLANK and SOUND_MECH_TRACK_RUMBLE, while hover frames receive SOUND_MECH_HOVER_THRUST, SOUND_MECH_HOVER_IDLE_PULSE and SOUND_MECH_HOVER_IDLE.

The eight prefabs were already structurally validated as no-leg-pair profiles. I did not add or rename any leg prefabs, cockpit parts, torso models, weapons or gameplay controls.
