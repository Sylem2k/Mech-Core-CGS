CGS MECH CORE — ENGINE STARTUP FOUNDATION — OCTOBER 27, 2026

GOAL
I'm building a shared reusable engine, cockpit, fuel and repair system for walkers, tracked mechs and hover mechs. I will adjust physical switch, engine, fuel and repair points independently on each mech size using Workbench PointInfo controls.

WHAT I ADDED TO CORE
- Scripts/Game/CGS_Engine/CGS_MechEngineComponent.c
  - Server-authoritative OFF -> STARTING -> RUNNING -> OFF state machine.
  - Adjustable startup time (3 seconds in these test frames); default OFF in these tests.
  - RplProp state for multiplayer clients; versioned startup completion avoids completing an aborted start.
  - Methods for future HUD use: GetEngineState, IsRunning, IsStarting, GetEngineStateName.
  - Five optional editable root-local PointInfo positions: EnginePoint, StartButtonPoint, StopButtonPoint, FuelPoint and RepairPoint.
  - Fuel and repair positions are reserved for the next components and DO NOT consume fuel or repair damage yet.
  - ServerStart/ServerStop check the actor is the actual occupant of the pilot compartment.
- Scripts/Game/CGS_Engine/CGS_MechEngineActions.c
  - CGS_MechEngineStartAction and CGS_MechEngineStopAction.
  - These follow the existing ScriptedUserAction pattern, and the server performs the final pilot permission check.

WHAT I ADDED TO MW TEST FRAMES
Only three Light frame .et files were modified:
- Prefabs/Vehicles/Mech/Frames/Light_Mech_Base.et (existing walker)
- Prefabs/Vehicles/Mech/Frames/Light_Mech_Frame_Tracked.et
- Prefabs/Vehicles/Mech/Frames/Light_Mech_Frame_Hover.et

Each test root has the optional CGS_MechEngineComponent, its five PointInfo offsets, two independently repositionable ActionsManager UserActionContext Position PointInfo buttons, and the start/stop scripted actions.
The offsets used are provisional and must be placed onto the visible cockpit console on each prefab in Workbench.
The actions use short interaction ranges and only show for the seated pilot.

IMPORTANT CURRENT LIMITS
This is a SMALL TEST FOUNDATION. I have NOT yet:
- connected OFF/STARTING state to drive lockout or weapon/sprint permission
- added fuel quantity, consumption, refueling, engine health, repair actions or repair materials
- added engine sounds, startup/shutdown ACP events or VFX
- added fuel/engine indicators to BFA_MechHUDDisplay
- built separate physical button meshes or demonstrated that root-owned interaction prompts can be selected while seated inside the cockpit
- configured medium, heavy or assault test prefabs

I intentionally left all existing movement scripts, walker IK, torso twist, weapon and cockpit scripts, and existing audio projects untouched. Existing mechs NOT in the three test frames are unaffected.
This should not be merged into main before Enfusion compilation and seat-action testing.
