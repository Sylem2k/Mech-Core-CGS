SYMPTOM
I tested my Light/Medium/Heavy/Assault tracked and hover frame variants, but neither tracks nor hover made any sound. The Workbench log from 2026-10-27 around 05:13 UTC shows the tracked and hover entities spawning successfully and the game running. The log does NOT show an explicit audio event failure, but it does contain unrelated SCR_VehicleTagData.InitData null-pointer errors on entering vehicles.

ROOT CAUSE FOUND IN SOURCE
In Core Sounds/SampleMech.acp, the five new SOUND_MECH_TRACK_CLANK, SOUND_MECH_TRACK_RUMBLE, SOUND_MECH_HOVER_THRUST, SOUND_MECH_HOVER_IDLE_PULSE and SOUND_MECH_HOVER_IDLE MixerClass connections had mistakenly been appended AFTER the closing brace of the mixer's ins block. All five new sound classes, shader nodes, banks and WAV references existed, but the output mixer's active ins block contained ONLY the two original walker sounds, SOUND_MECH_STEP and SOUND_MECH_SERVO.

CORRECTION
I moved all five ConnectionsClass con:97001 to con:97005 entries INTO MixerClass "8203" -> ins. I did not modify the samples, the event IDs or the original two sound paths. The structural validation finds all SEVEN connections inside the mixer input and balanced braces; this is an actual source fix, not a promise that Workbench audio playback has already been verified.

The eight MW prefabs already have their correct audio components and three/two event mappings on the previous branch. I did not re-edit them unnecessarily. Both new repair branches have been merged forward with the latest main to preserve newer content, including any prefab edits.
